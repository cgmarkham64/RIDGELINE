### Reusable patterns from this session (in addition to prior sessions' list, still below)

- **Top-level aggregator hook for a God component with many sub-hooks**: when a component calls 6+ hooks just to wire up its own state (persisted state, autosave, scan, zone-detection, dialog, lookup, actions, checklist), and the orchestrator's own line count is still over budget just from the *wiring*, wrap all of them in one `use<Feature>StageState(...)` hook that returns a single object (`{ s, scan, zoneDetection, dialog, lookup, actions, checklist }`). The orchestrator then makes one hook call and destructures. See `permitsStage.hooks.ts`'s `usePermitsStageState`.
- **Extract JSX-heavy `&&`-conditional tails (loading overlays + modals) into a dedicated `<XOverlays>` component** — pulls several `&&` branches (each a complexity point) out of the parent for free, same idea as the "move conditional into child" pattern from prior sessions but specifically for the multiple-overlay tail every stage component tends to accumulate. See `PermitsOverlays.tsx`.
- **`null`→`undefined` normalization at the state-declaration site removes downstream `?? undefined` calls** — if a piece of state feeds a component prop typed `X | undefined` (a plain optional prop, not `X | null`), declare the state as `useState<X | undefined>(undefined)` from the start rather than `useState<X | null>(null)` + `?? undefined` at every consumption site. Each `?? undefined` is itself a complexity point under this repo's `complexity` rule.
- **Guard-clause extraction for real type narrowing without `!`**: when an early-return guard has 4+ `||`-joined conditions AND you need real type narrowing afterward, extract the guard into a small function returning `T | null` (bundling the narrowed values), rather than keeping the guard inline. Keeps the caller's own complexity low while still satisfying "no unchecked `as`/`!` assertions." See `permitsStage.hooks.ts`'s `resolvableZoneContext`.
- **The `complexity` rule's `?.`/`??` counting (documented in a prior handoff) compounds across independently-trivial lines** — a function with 4-5 one-line `trip?.field ?? fallback` expressions can hit double-digit complexity even with zero `if`/`else`. When this happens, pull each such expression into a tiny named pure function (`computePartySize`, `computeLocationLabel` in `permitsStage.hooks.ts`) — the complexity moves to the (now cheap, isolated) helper and out of the caller.

### Two non-obvious lint-tool findings from prior sessions (still true, still relevant)

1. **`eslint-plugin-react-hooks` v7's ref-safety analysis** flags `ref={someObject.someRefField}` as "Cannot access ref value during render" specifically when the ref is threaded through a custom hook's *returned object* and consumed via `ref=` in a **different component** than the one that called the hook. It does NOT fire when the hook is called and the ref is consumed in the same component. **Fix pattern**: keep the `useRef()`-owning hook call and the `<input ref={...}>`/`<div ref={...}>` JSX in the same component; if you need to split that component further, keep the ref+its element together and pass everything else down as props.
2. **The `complexity` rule counts optional-chaining (`?.`) and nullish-coalescing (`??`) as branches**, same as `&&`/`||`/ternaries/`if`. Guard once on the parent being undefined, then access non-optional fields directly instead of chaining `?.`/`??` per field.

### Recurring decomposition pattern used across every file this multi-session effort

For each God component: pull out (a) an orchestrator that just composes children and holds top-level state, (b) presentational subcomponents per visually-distinct section (each gets `show`/data props, not raw `&&` conditionals wrapping them in the parent), (c) one or more custom hooks for state+handlers that belong together (data fetching, derived values, checklist/progress), and (d) a `*.helpers.ts`/`*.types.ts` pair for pure functions and shared types. When a single component is still over budget after one level of extraction, extract again. Don't be afraid of 15-20 files for a single "God component" — that's the expected shape here, not a sign you've gone too far.
